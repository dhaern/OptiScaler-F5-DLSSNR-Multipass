# Spatial tracking and bounded late fallback

Creation-time heap/root metadata is the primary path. Command lists retain a device-generation association across Reset; descriptor strides, CPU-handle lookup and loose descriptors are device-scoped. Known SAMPLER/DSV heaps have metadata but no descriptor shadow. Successful primary binding/lookup never enters late-heap resolution, loose lookup or root inference.

Device records are established at cold installation/creation boundaries, including same-runtime devices created through a device factory rather than the D3D12CreateDevice export. Matching creation-method addresses establish hook coverage, **not** that earlier objects were observed. A small device-private lifetime marker invalidates its generation without retaining the device. The 64 process-lifetime generation slots are not recycled; capacity/attachment failure refuses replacement on that generation. Different-runtime creation code is unsupported rather than assumed tracked.

Only a missing old heap may enter `ResolveBoundHeap`. It uses 256 bounded inline records, a nonblocking owner and one GetDesc/GetDevice observation per retained record. It does not allocate a heap shadow, enter the creation registry lock, migrate a heap-sized range or wait at binding. GPU lookup of such a heap reads the current device-local loose descriptor; no frame's constants/textures are cached. The temporary GetDevice reference is released immediately. Capacity/busy/invalid-owner failure leaves the game's pass intact.

Object-address/range reuse is invalidated by the observed creation hook before publishing fresh primary metadata. This relies on the supported device's verified creation-hook coverage and the application's ordinary D3D12 object-lifetime contract; it is not a promise about arbitrary foreign COM wrappers or unhooked runtimes. Retired device generations and inactive heap references are never reused for another device. Published metadata remains alive for existing tracker readers, as in the original registry.

Loose storage is allocated lazily by evidenced unknown CPU-descriptor writes/copies, not by draw/bind lookup. Known registration failure disables unknown-descriptor fallback for that device; known root records with missing/failed parsing cannot enter inference. Root-registration allocation failure similarly disables unknown-root inference without discarding unrelated successful primary layouts. Inference remains fallible and recomputes bindings from each pass; attempts and resolved bindings are distinct from replacements.

Every 600 application presents, aggregate per-device counters report actual late-heap attempts/success/ignored/failure/queries, loose operations/writes/failure, root attempts/resolved/failure, unavailable flags and generation state. These are ordinary diagnostics, not a file toggle or test control. No shader, jitter, replay, depth-finder, HUD-less or backend algorithm is changed by this refactor. Existing independent lifecycle/visual limitations still require their own acceptance evidence; a successful fallback count is not pixel or frame-generation validation.
